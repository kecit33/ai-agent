## 二、两种交互模式

### 模式 A：内置演示模型（无需任何 Key）

打开页面直接聊。系统内置一个规则模型（mock-rule-v1），能正确路由到全部 12 个 MCP 工具，
链路完整可验收，适合快速演示。

### 模式 B：DeepSeek 真实模型（自带 Key，推荐）

1. 在左侧边栏「模型设置 · 自带 KEY」处粘贴你的 DeepSeek API Key；
2. Key **只保存在你自己的浏览器 localStorage**，不写入服务器、不进日志；
3. 之后每句对话都会用 DeepSeek 真实模型回答（侧边栏会显示 `模型：deepseek-chat（你的 Key）`）；
4. Key 无效时会得到明确的中文提示（"DeepSeek 返回 401 鉴权失败"），不会白屏。

> 已实测：2026-10-25 用真实 Key 在线上完成多轮对话，
> "查一下北京的天气" → 真实调用天气工具 → "那上海呢？" 正确继承上下文并做京沪对比。

## 四、与其他小组部署方式对比

| 小组 | 前端 | 部署方式 | 在线交互 | 密钥处理 |
|---|---|---|---|---|
| 借物小管家（6人组） | Streamlit | Streamlit Community Cloud | ✅ 组内口令进入 | Key 存平台 Secrets |
| Akida1122 组（8人组） | HTML + FastAPI | 仅本地 127.0.0.1:8000 | ❌ | 本地 .env |
| 惊蛰破阵曲组（5人组） | Streamlit | 仅本地 streamlit run | ❌ | 本地 .env |
| **本组（小枢）** | 原生 HTML + FastAPI | 云端托管发布 | ✅ 无需口令，直接访问 | **访问者自带 Key，仅存浏览器，服务器零密钥** |

本组的差异化设计：**服务器上不存任何密钥**。线上环境默认跑演示模型；想用真实模型，
访问者在自己的浏览器里填自己的 Key，密钥只在当次请求的内存中使用，随用随弃。
相比"Key 存平台 Secrets"的方式，多用户各自用各自的 Key，也无平台泄露风险。

## 五、常见问题

| 现象 | 原因与处理 |
|---|---|
| 打开是 403 | 没带 `?sharecode=UCW4DQSI7B`，用文首完整链接 |
| 回复带【Mock 模型】前缀 | 当前是演示模式；想用真模型，在侧边栏填 DeepSeek Key |
| 提示 "401 鉴权失败" | Key 错误或余额不足；检查后重填，或清空用演示模式 |
| 写文件操作没反应 | 看屏幕中央是否有确认弹窗，点「允许执行」后才会写入 |
| 天气查询失败 | 线上服务器需能访问 open-meteo.com，偶发超时可重试一次 |

# 打开 http://127.0.0.1:8000
