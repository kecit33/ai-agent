## 优化 1：工具返回值可展开查看 —— 补上"可观测"要求

**问题**：作业要求"前端可查看每一次工具调用的参数与返回"。后端 `reply_to_dict` 一直有
`output_preview` 字段（每个工具返回的前 300 字符），但前端**从来没渲染它**——
用户只能看到"调用了 `weather_get`"，看不到它到底返回了什么，"结论来自工具真实返回"缺乏凭证。

**改动**：`src/web/static/index.html`
- 轨迹行加 `▶` 箭头，点击展开该工具的真实返回值（`<pre class="trace-out">`）；
- 补 `escapeHtml()`，工具返回内容一律转义后再插入，避免返回里带 HTML 造成注入；
- 顶部提示语改为"点击工具轨迹可展开返回值"。

**验证**：本地抓页面确认 `trace-out` 元素存在；线上发布后可点开核对。

## 优化 2：网页端语音输入/输出 —— 补上加分项

**问题**：`src/voice/` 只有 Python 端的 Whisper + TTS，**必须装可选依赖、只能在 CLI 用**，
网页界面上一个语音按钮都没有。作业加分项写的是"语音输入/输出"，验收老师打开网页什么也看不到。

**改动**：`src/web/static/index.html`
- 🎤 按钮：浏览器原生 `Web Speech API` 识别（zh-CN），点一下说话，**说完自动填入并发送**；
- 🔈 朗读开关：浏览器 `speechSynthesis` 播报助手回复（截断 220 字，避免长文念太久）；
- 两者**零依赖**：不装任何 Python 包、不发起一次网络请求；浏览器不支持时按钮自动隐藏，不影响主功能；
- 本地 CLI `--voice` 路线保留不变。

**验证**：页面含 `SpeechRecognition`/`speechSynthesis` 关键字与 `#mic`/`#tts` 元素（已抓页面确认）。
（语音识别需麦克风授权，属浏览器行为，需你在页面上亲自点一次确认。）

## 优化 3：HTTP 抓取加域名白名单 —— 堵住 SSRF

**问题**：`http_get_json` 只校验了 `https://` 前缀，**没限制域名**。模型一旦被提示注入诱导，
就能让服务器以自身身份访问 `https://169.254.169.254/latest/meta-data`（云元数据）或内网地址，
这是标准 SSRF。之前的限制清单里写了这个风险，现在把它修掉。

**改动**：`src/mcp_server/tools_net.py`
- 新增 `ALLOWED_DOMAINS` 白名单（open-meteo、wttr.in、github 公开接口），
  支持 `HTTP_ALLOWED_DOMAINS` 环境变量追加；
- 主机名**精确匹配**，不用后缀通配——否则 `open-meteo.com.evil.net` 会绕过；
- 命中拒绝时返回"域名不在白名单内 + 当前允许列表"，让模型知道边界在哪而不是盲目重试。

**验证**（新增单测 `test_http_domain_whitelist_blocks_ssrf`）：
```
https://api.open-meteo.com/x        -> 允许
https://evil.com/x                  -> 拒绝
https://open-meteo.com.evil.net/x   -> 拒绝（后缀伪造也无法绕过）
https://169.254.169.254/...         -> 拦截（云元数据地址）
```

## 优化 4：待办去重 —— 修真实演示暴露的毛病

**问题**：16 条真实演示中，待办列表出现两条重复条目，模型当时自己发现了并建议删除，
但工具层本就该拦住——重复数据不该进库。

**改动**：`src/mcp_server/tools_todo.py`
- `todo_add` 先按"标题 + 截止时间"查未完成任务，命中则返回
  `{"duplicate": True, "id": 原ID, "message": "已存在相同待办 #N，未重复添加"}`，不重复插入。

**验证**（新增单测 `test_todo_add_deduplicates_same_item`）：连续添加两次 → 第二次
`duplicate=True` 且返回同一个 ID。
